# Программа «Подтягивания 5×30» — дизайн

**Дата:** 2026-09-16
**Статус:** утверждён, готов к плану реализации

## Контекст

Есть готовая 30-недельная прогрессия по подтягиваниям: 5 подходов за тренировку,
число повторений в каждом подходе растёт от недели к неделе. Нужно встроить
её в СенПая (бот учёта тренировок, `Brotherhood - bot/SenPai/bot.py`) и в
личный кабинет тренировок (`Brotherhood - bot/Nutrition/training.html`,
зеркалируется вручную в `Training-deploy/training/index.html` для заливки на
сайт).

Сейчас подтягивания в СенПае — обычное упражнение из `EXERCISE_CONFIG`: бот
просит одно число в день, оно пишется в Supabase (`exercise_logs`), разряд
(Новичок → Легенда додзё) считается по PR (максимальному значению за всё
время). Кабинет отражает то же самое через свой мирроring `EXERCISE_CONFIG` в
JS.

## Цель

Добавить для подтягиваний отдельный слой «программы»: бот показывает целевые
числа на сегодня по всем 5 подходам текущей недели плана и спрашивает,
выполнено или нет — без изменения существующей механики разрядов.

## Данные (Supabase)

Новая таблица `pullup_program`:

| поле | тип | описание |
|---|---|---|
| `user_id` | text, PK | `tg_<telegram_id>`, как везде в проекте |
| `current_week` | int | 1–30 |
| `started_at` | date | когда создана запись, для справки/отладки |

Отдельная от `exercise_logs` — там продолжает писаться одно PR-число в день,
как раньше, логика разрядов не меняется.

## Бот (СенПай)

**Диагностика старта.** Первый раз, когда участник выбирает «Подтягивания» в
`/go`, а строки в `pullup_program` для него ещё нет — бот спрашивает:
«Сколько подтягиваний одним подходом можешь сделать сейчас?». По ответу
находится максимальная неделя плана, где `Подход1 <= ответа`; если ответ
меньше 6 (минимум таблицы) — неделя 1. Создаётся запись с этой неделей.

**Показ плана.** При каждом следующем выборе «Подтягивания» бот показывает
5 целевых чисел текущей недели и две кнопки: **✅ Сделал** / **❌ Не сделал**.

- **Не сделал** → неделя не меняется, в `exercise_logs` ничего не пишется,
  короткое подтверждающее сообщение («Ок, повторим в следующий раз»).
- **Сделал** → в `exercise_logs` пишется одно число = максимум из 5 целевых
  чисел текущей недели (это то же самое PR-значение дня, что и раньше, разряд
  считается от него без изменений). Неделя сразу `+1`. На неделе 30 после
  «Сделал» — сообщение «Программа завершена 🏆», дальше номер недели не
  растёт (программа фиксируется на 30).

**`/stats`.** Для подтягиваний добавляется вторая строка под существующим
разрядом: «Программа: неделя X из 30» (или «Программа завершена 🏆» на
неделе 30).

## Личный кабинет

В карточке «Подтягивания» (`training.html`, `renderTodayCard`) добавляется
компактный блок под существующим содержимым карточки: «Неделя X / 30» и 5
целевых чисел текущей недели. Данные читаются из `pullup_program` через
Supabase REST (`fetchExerciseHistory`-подобный запрос). Если строки в
`pullup_program` ещё нет (участник ещё не начинал программу через бота) —
блок не показывается.

Графика по всем 30 неделям в этой итерации нет — можно добавить отдельно
позже, если понадобится.

`Training-deploy/training/index.html` — точная копия `Nutrition/training.html`
для ручной заливки на сайт; оба файла правятся одинаково в рамках этой
задачи.

## Совместимость с разрядами

Разряды по подтягиваниям (Новичок…Легенда додзё), их пороги и способ расчёта
(по PR из `exercise_logs`) не меняются. Программа — источник числа, которое
попадает в `exercise_logs`, когда участник нажимает «Сделал»; вне программы
(если участник вручную зайдёт и введёт число другим путём — такого пути в
новом флоу для подтягиваний больше нет) логика не предусмотрена.

## Edge cases

- Ответ на диагностику вне диапазона таблицы (< 6) → неделя 1.
- Ответ на диагностику очень большой (> 26) → неделя 30 (потолок таблицы).
- Неделя 30 + «Сделал» → остаётся на 30, статус «завершена», `exercise_logs`
  всё равно обновляется (PR продолжает расти, если участник сильнее плана).
- Нечисловой ответ на диагностику → переспросить, как в существующей
  обработке ввода чисел в боте.

## Вне скоупа

- График прогресса по неделям в кабинете.
- Изменение системы разрядов.
- Программы для других упражнений (структура задела под них не делается —
  это отдельная фича, если понадобится).
